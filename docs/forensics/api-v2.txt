Quick Start
Everything you need to start generating videos with the Golpo REST API v2.

Auth header
x-api-key: YOUR_API_KEY 
Content-Type
application/json 
Best for
Server-to-server integrations, automation workflows, internal dashboards, partner apps

Prerequisites
Valid API plan · API key issued per workspace · HTTPS requests only · files must be under 10 MB

NOTE: POST /api/v2/videos/generate requires x-api-key . Returns 403 with the message “API v2 requires API key authentication. Provide ‘x-api-key’ header.” if the header is missing. 
Your API base URL is provided when you create an API key in the dashboard. All requests must be made over HTTPS. 

Video Endpoints
Seven REST endpoints covering the full video lifecycle — generate, list, retrieve, update, delete, job status, and user credits.

POST /api/v2/videos/generate 
Generate a video from a prompt or script. JSON body, x-api-key required.

JavaScript Python .NET Java curl 
generate.js Copy 
import fetch from "node-fetch";

const API_KEY = "api-key"; // Replace with your Golpo API key

const payload = {
prompt: "Explain the quarterly roadmap",
background_track: "engaging"
};

const BASE_URL = "{BASE_URL}"; // You will receive this when creating an API key
const response = await fetch(`${BASE_URL}/api/v2/videos/generate`, {
method: "POST",
headers: {
"Content-Type": "application/json",
"x-api-key": API_KEY
},
body: JSON.stringify(payload)
});

const data = await response.json();
console.log(data); 
Run with: node --env-file=.env generate.js

GET /api/v2/videos 
Retrieve videos belonging to the authenticated user. Supports limit and offset query params. x-api-key required.

JavaScript Python .NET Java curl 
list-videos.js Copy 
import fetch from "node-fetch";

const BASE_URL = "{BASE_URL}"; // You will receive this when creating an API key

// Query params:
// limit — max number of videos to return (optional)
// offset — number of videos to skip (optional, for pagination)
const response = await fetch(`${BASE_URL}/api/v2/videos?limit=10&offset=0`, {
headers: {
"x-api-key": "api-key"
}
});

const data = await response.json();
console.log(data.videos); // array of video objects
console.log(data.total); // total number of videos 
Run with: node --env-file=.env list-videos.js

Request Body
Full parameter reference for POST /api/v2/videos/generate.

Only prompt is required. All other parameters are optional. 
Parameter Type Default Required Description 
prompt string — Required Main prompt/topic for the video.

reference_source array[string] None Optional List of document URLs (https/s3) used as reference material. Use /upload-file to obtain URLs; server-side callers may also pass local file paths.

narration_instructions string "" Optional Describe how the narration voice should sound — accent, tone, pace, and delivery style.
Examples: "Speak in a warm British accent with a calm, professorial tone", "Fast-paced sports commentator style". 

enable_script_only_mode boolean false Optional Only generate the script — skip TTS and video rendering. Status response returns script_text.
NOTE: This parameter will not work with own_narration_source (own-narration mode). Requests will follow the standard own_narration workflow regardless of the parameter value. 

custom_script string None Optional Use a script you supply instead of generating one. Capped at approximately 15 estimated minutes.
NOTE: Scripts longer than ~15 estimated minutes are rejected with 422. If timing is also set, it must be greater than or equal to the estimated script duration. 
Embedding paired [START][IMAGE N]...[END][IMAGE N] and [START][VIDEO N]...[END][VIDEO N] markers in your script controls where your uploaded custom_images and custom_videos appear. See the Inserting Images in Script and Inserting Videos in Script sections for the placement rules — markers that violate the format are silently dropped. 

onscreen_text_from_script_only boolean false Optional Generate on-screen text using script-source content only. No extra labels, captions, titles, or other words are added.
NOTE: Supports normal prompt flow, script-based flow, and own-narration flow. Source text comes from generated script (prompt), provided script (custom_script), or narration transcription source (own_narration_source). 

narration_voice string "female-1" Optional Narration voice.
Allowed values: "female-1" (default), "female-2", "female-3", "female-4", "female-5", "female-6", "female-7", "male-1", "male-2", "male-3", "male-4", "male-5", "male-6", "male-7". 

enable_color boolean true Optional Enable color video generation pipeline.

narration_language string "en" Optional Language for narration. Lowercase only — accepts language keywords (e.g. "english", "hindi"), ISO 639-1 codes (e.g. "en", "hi"), or code-switch variants (e.g. "hi-en").

background_track string None Optional Background music track.
Allowed values: "jazz", "lofi", "dramatic", "engaging", "hyper", "inspirational", "documentary". 

video_orientation string "horizontal" Optional Video orientation: "horizontal" (16:9) or "vertical" (9:16).

enable_podcast_engine boolean false Optional When true, generate audio-only podcast output (no video). Status response returns podcast_url.

timing string "1" Optional Video/podcast duration in minutes (as string) or "auto" to let the system determine it.
Supported values: "0.25", "0.5", "1", "2", "4", "8", "10", "15", "auto". 
NOTE: "15" requires Enterprise Custom, or Scale with the Longer Videos add-on enabled. Other API plan/add-on combinations receive a 403. 

watermark boolean false Optional Include a watermark in the video.

custom_logo string None Optional Custom logo URL (https/s3). Use /upload-file first; server-side callers may also pass local file paths.

logo_position string None Optional Logo placement. Allowed values: "tl" (top-left), "tr" (top-right), "bl" (bottom-left), "br" (bottom-right).
NOTE: Only valid when watermark=true or custom_logo is provided. Setting logo_position without either is rejected with 422, since no logo or watermark would render. 

visual_instructions string "" Optional Visual instructions to guide how the video looks.
Examples: "Show more graphs and charts", "Cinematic transitions", "Dark moody aesthetic with neon accents". 

golpo_video_engine string "golpo_canvas" Optional Video generation engine: "golpo_canvas" (default) or "golpo_sketch".
NOTE: When using golpo_canvas, canvas_style_variant is required. When using golpo_sketch, sketch_style_variant is required. Setting either to null is rejected with 422. 

canvas_style_variant string "chalkboard_color" Optional Golpo Canvas style variant. Unsuffixed values select the Expanded profile. For the ten pre-Notebook style families, append '_compact' to select the Compact profile. Notebook is Compact-only and remains unsuffixed.
Allowed values: "chalkboard_bw", "chalkboard_bw_compact", "chalkboard_black_on_white", "chalkboard_black_on_white_compact", "chalkboard_color", "chalkboard_color_compact", "whiteboard", "whiteboard_compact", "modern_minimal", "modern_minimal_compact", "playful", "playful_compact", "technical", "technical_compact", "editorial", "editorial_compact", "sharpie", "sharpie_compact", "illustrations", "illustrations_compact", "notebook_infographic". Required when golpo_video_engine is "golpo_canvas". 

sketch_style_variant string "classic" Optional Golpo Sketch style variant.
Allowed values: "classic" (default), "improved(beta)", "formal", "crayon", "dry_erase", "professional_clean", "creative", "infographics", "chalkboard_black_on_white". Required when golpo_video_engine is "golpo_sketch". 

custom_style string None Optional Use your own custom visual style. First save a style (from an image URL, a video URL, or a text description) with POST /api/v2/custom-styles , then pass its id here. Works with both Golpo Canvas and Golpo Sketch — when set, canvas_style_variant / sketch_style_variant are ignored.
NOTE: Requires a Business or above plan. Not allowed with enable_podcast_engine=true (422). 

own_narration_source string None Optional URL (https/s3) to an audio or video file to use instead of generating script and TTS. Server-side callers may also pass local file paths.
Useful for generating a video from your own existing audio or video narration. 

use_ai_audio_at array[integer] None Optional List of 1-indexed positions in custom_videos whose original audio should be replaced with AI-generated narration. Videos not listed keep their original audio.
NOTE: Only valid when custom_videos is provided. Length must not exceed the number of custom_videos. 

custom_images array[string] None Optional List of image URLs (https/s3) to insert into the video. Server-side callers may also pass local file paths.

custom_images_description array[string] None Optional List of descriptions for custom images (one per image).
NOTE: Required when custom_images is provided. Must have the same length as custom_images. 
Descriptions tell the Golpo AI what each image shows, so it can place each image at the right moment in the script and reference it in the narration. More specific descriptions produce more contextually accurate videos. 

keep_original_images array[boolean] None Optional List of booleans indicating whether to use each image as-is without AI processing (one per image).
NOTE: Only valid when custom_images is provided. Length must not exceed the number of custom_images. 

disable_image_animation array[boolean] None Optional List of booleans indicating whether to skip animation for each image (one per image).
NOTE: Only valid when custom_images is provided. Length must not exceed the number of custom_images. 

custom_videos array[string] None Optional List of video URLs (https/s3) to insert into the video. Server-side callers may also pass local file paths.

custom_videos_description array[string] None Optional List of descriptions for custom videos (one per video).
NOTE: Required when custom_videos is provided. Must have the same length as custom_videos. 
Descriptions tell the Golpo AI what each video shows, so it can cut to each clip at the right moment in the script and frame the surrounding narration. More specific descriptions produce more contextually accurate videos. 

visibility string None Optional Video visibility. Allowed values: "public" (appears in the Golpo gallery) or "private".

video_id string None Optional Optional custom video/job id assigned by the caller.

reference_images array[string] None Optional List of reference image URLs (https/s3) for problem-solving mode. The video is generated around the provided images. Server-side callers may also pass local file paths.
Best suited for explaining math, science, or any problem captured as an image — pair with timing: "auto" so the Golpo AI picks a duration that matches the complexity of the problem. 

pen_animation_style string None Optional Pen cursor animation style. Allowed values: "stylus", "marker", "pen".
NOTE: Only supported with the Golpo Canvas engine. Setting this field with "golpo_video_engine": "golpo_sketch" is rejected with 422. 

visual_animation_style string "auto" Optional Visual animation style for generated visual components in Golpo Canvas (for example: illustrations, diagrams, icons, arrows, and annotations). Default value: "auto" (Golpo Canvas engine decides the animation style). Allowed values: "auto", "fade_in", "sketch".
NOTE: Only supported with the Golpo Canvas engine. Setting this field with "golpo_video_engine": "golpo_sketch" is rejected with 422. 

own_narration_video_mode boolean None Optional Deprecated compatibility field. true shows the narration video; false uses only its audio. New requests should select own_narration_video_layout directly.
NOTE: Existing payloads remain supported. true without a layout keeps the circular PiP behavior. 

own_narration_video_position string "right-bottom" Optional Placement of the narration video. PiP uses the full corner. Split layout reads left/right for horizontal videos and top/bottom for vertical videos. Allowed values: "left-top", "right-top", "left-bottom", "right-bottom" (default).

own_narration_video_layout string None Optional Narration-video layout: "round_overlay" uses a circular corner overlay; "side_by_side" uses left/right regions for horizontal output and top/bottom regions for vertical output. Omit for narration audio only.
Existing integrations may retain "pip" or "split" together with the deprecated own_narration_video_mode=true. New integrations should use the canonical layout values without the boolean. 

own_narration_split_size string "50%" Optional In side_by_side layout, the narrator share of the active axis: width horizontally or height vertically. Allowed values: "25%", "30%", "35%", "40%", "50%".

own_narration_video_fit string "crop" Optional "crop" fills the narrator card without distortion and enables framing focus. "full" keeps the complete narrator frame using the existing stretch behavior.

own_narration_focus_position number 50 Optional Framing slider from 0–100 when fit is crop. Horizontal output: 0 keeps more left and 100 more right. Vertical output: 0 keeps more top and 100 more bottom.
NOTE: Only valid with own_narration_video_layout="side_by_side" and own_narration_video_fit="crop". 

own_narration_webcam_crop_x number | null None Optional Deprecated 0–1 framing value retained for compatibility. Use own_narration_focus_position (0–100) instead.

avatar_id string None Optional Turn on AI Presenter: an avatar that lip-syncs the narration. Pass a Golpo avatar id from GET /api/v2/avatars/stock (for example "stock-maya-v1") or the id of a Ready custom avatar created with POST /api/v2/avatars.
NOTE: Golpo avatars use 3 credits/min. Custom avatars use 5 credits/min. Cannot be combined with own_narration_video_layout or own_narration_video_mode=true; own_narration_source audio is allowed (up to 15 minutes) and the avatar lip-syncs it. 

avatar_layout string "auto" Optional Layout: "auto" (Auto: uses approved layouts automatically), "side_by_side" (Side by side in horizontal videos, Top and bottom in vertical videos), "round_overlay" (Round overlay: circular corner overlay), or "fullscreen" (Full screen: presenter fills the complete frame). Requires avatar_id.
A layout the avatar cannot render returns 422 avatar_layout_unavailable. Check available_layouts on GET /api/v2/avatars/{avatar_id}. 

avatar_position string "right-bottom" Optional Presenter placement: "left-top", "right-top", "left-bottom", "right-bottom". Round overlay uses it as the corner; Side by side uses the side (Presenter left / Presenter right); Top and bottom uses top or bottom (Presenter top / Presenter bottom). Requires avatar_id.

avatar_split_size string saved split, else "30%" Optional Presenter size: "25%", "30%", "35%", "40%", "50%" of the width (Side by side) or height (Top and bottom). Defaults to the split saved in the avatar layout_config. Not valid with avatar_layout="round_overlay". Requires avatar_id.

avatar_framing object None Optional The orientation_framing object returned by POST /api/v2/avatars/{avatar_id}/video-preflight. Pass it to accept a best-effort crop for this video. Requires avatar_id.

custom_videos_avatar_modes object None Optional Avatar during this clip, keyed by the 1-indexed custom_videos position: "off" (Hide avatar: video uses the full frame) or "round_overlay" (Show avatar: round corner overlay). Example: {"1": "off"}. Requires avatar_id and custom_videos.

scene_pacing string "normal" Optional Pacing level: "normal" (15s max per scene) or "fast" (10s max per scene). Works with both Golpo Canvas and Golpo Sketch.
NOTE: Animated frame_transition values are only available with scene_pacing "normal". Combining them with "fast" is rejected with 422. 

frame_transition array[string] ["none"] Optional How a finished frame moves into the next frame. Allowed values: "none" (hard cut), "left", "right", "up", "down", "zoom_in", "zoom_out". Send several values (for example ["left", "zoom_in"]) and one is picked at random for every frame change. Works with both Golpo Canvas and Golpo Sketch.
NOTE: Only available with scene_pacing "normal". Any value other than ["none"] combined with scene_pacing "fast" is rejected with 422. 
NOTE: "none" cannot be combined with other values, and each value must be its own array item (not a comma separated string). 
Only works with Golpo Canvas and Golpo Sketch. See the Frame Transition section for details. 

transition_hand_animation boolean false Optional Have an animated hand push every slide of frame_transition. Accepts only true or false.
NOTE: true requires frame_transition to contain at least one of "left", "right", "up", "down", and cannot be combined with "zoom_in" or "zoom_out". Otherwise the request is rejected with 422. Like frame_transition, it needs scene_pacing "normal". 

onscreen_text_language string None Optional Language for on-screen text. Same value space as narration_language. Useful when displayed text should differ from the narration language.
NOTE: Only supported with the Golpo Canvas engine. Setting this field with "golpo_video_engine": "golpo_sketch" is rejected with 422. 
If omitted, on-screen text uses the same language as narration_language. 
Example: narration_language: "hindi", onscreen_text_language: "english" — narration in Hindi, on-screen text in English. 

language_variants array[string] None Optional Generate additional language versions of the video alongside the primary narration_language . Provide an array of supported languages (e.g. ["spanish", "french", "hi"]). A separate video will be generated for each specified language.
Each language version is billed as a separate render. For example, a 2-minute video with 2 additional languages is billed as 3 renders × 2 minutes. Duplicate languages, including the primary narration_language, are not allowed and will return a 400 error. 
NOTE: All language variants use the same prompt, duration, voice, and visual settings. Only the narration_language changes for each variant. 

variant_visuals_mode string "shared" Optional Controls how visuals are generated across language variants. shared (default) reuses the primary video's visuals across all language variants. per_language generates separate visuals for each language variant.

Custom Style Endpoints
Save your own visual style from an image URL, a video URL, or a text description, then reference it by custom_style_id in custom_style on POST /api/v2/videos/generate . Works with both Golpo Canvas and Golpo Sketch.

Create your custom style first, then reference it by custom_style_id
POST /custom-styles GET /custom-styles POST /videos/generate with custom_style: "<id>" 

NOTE: Available from the Business plan and above. All endpoints require x-api-key . 

Endpoint Method Description 
{BASE_URL}/api/v2/custom-styles GET List your saved styles (newest first) 
{BASE_URL}/api/v2/custom-styles POST Save a style from an image URL, video URL, or text description 
{BASE_URL}/api/v2/custom-styles/{custom_style_id} GET Get one saved style 
{BASE_URL}/api/v2/custom-styles/{custom_style_id} DELETE Delete one saved style 

Request body — POST /api/v2/custom-styles 
Field Type Required Description 
style_name string (1–60) Required Display name for the style. 
source string (1–5000) Required An HTTPS URL to an image (moodboard, brand frame, illustration), an HTTPS URL to a video file (frames are sampled and analyzed for the still art style), or a free-text style description . Use /upload-file to host your own image or video and pass the returned file_url . 
kind string Optional Allowed values: "image" ( source is an HTTPS image URL), "video" ( source is an HTTPS video URL — frames are sampled and analyzed), or "text" ( source is a style description).

POST /api/v2/custom-styles 
Save a custom style from an HTTPS image URL, an HTTPS video URL, or a free-text description.

JavaScript Python .NET Java curl 
create-custom-style.js Copy 
import fetch from "node-fetch";

const API_KEY = "api-key"; // Replace with your Golpo API key
const BASE_URL = "{BASE_URL}"; // You will receive this when creating an API key

// kind: "image" (HTTPS image URL) | "video" (HTTPS video URL) | "text" (style description)
const payload = {
style_name: "Brand moodboard",
source: "https://cdn.example.com/brand-moodboard.png",
kind: "image"
};

const response = await fetch(`${BASE_URL}/api/v2/custom-styles`, {
method: "POST",
headers: {
"Content-Type": "application/json",
"x-api-key": API_KEY
},
body: JSON.stringify(payload)
});

const data = await response.json();
console.log("Style ID:", data.style.id); // pass as custom_style on /generate 
Run with: node --env-file=.env create-custom-style.js

AI Presenter (Avatar)
Add a lip-synced AI Presenter to any Golpo video. Use a ready-made Golpo avatar, or create a custom avatar from a portrait of yourself or a colleague.

Golpo avatar
Pick a Golpo avatar and pass its id as avatar_id . Ready to use, nothing to set up. Golpo avatars use 3 credits/min .

Custom avatar
Upload a portrait, approve its framing in each layout, and save it to My Avatars. Reuse it in any video. Custom avatars use 5 credits/min .

Custom avatar flow
Step 1

Base URL
https://api.golpoai.com Every avatar endpoint below is {BASE_URL}/api/v2/avatars/… , for example https://api.golpoai.com/api/v2/avatars/stock .

Auth header
x-api-key: YOUR_API_KEY JSON bodies use Content-Type: application/json ; the portrait upload uses multipart/form-data .

NOTE: All avatar endpoints need the x-api-key header; portal session tokens return 403. Avatars are private to the account that owns the key. Natural avatars, layout previews, and preflight have no creation credit. A Polished avatar costs 1 credit after successful creation.

Create a Custom Avatar
Four calls: upload, preview, create, and (for Polished avatars) wait until Ready.

1 Upload a portrait
POST {BASE_URL} /api/v2/avatars/upload 
Send multipart/form-data with image and kind=source . PNG, JPEG, or WebP, up to 10 MB.
Use a clear, front-facing photo, lit evenly, with the head and shoulders visible.
Leave some space above the head; tightly cropped faces fit fewer layouts.
One person only, no sunglasses or hands covering the face.
upload.sh Copy 
curl -X POST "{BASE_URL}/api/v2/avatars/upload" \
-H "x-api-key: $GOLPO_API_KEY" \
-F image=@portrait.jpg \
-F kind=source 

200 response Copy 
{
"success": true,
"upload": {
"object_url": "https://…/avatars/…/source-….jpg",
"content_type": "image/jpeg"
}
} 

For large files, call POST /api/v2/avatars/upload-url with {"content_type": "image/png"} . PUT the bytes to the returned url with the same Content-Type , then use object_url .

2 Preview the layouts
POST {BASE_URL} /api/v2/avatars/layout-preview 
Send the object_url and a layout_config . For every layout and orientation Golpo returns two images and tells you whether the presenter fits. It's the API version of the playground's Live preview: adjust Zoom, Horizontal position, and Vertical position, and call it again until every layout looks right.
frame_preview_url : the presenter beside "Your content" in a full Landscape 16:9 or Portrait 9:16 frame, exactly where the final video puts it. Set avatar_position ( left-top , right-top , left-bottom , or right-bottom , the default) to see other placements.
preview_url : the presenter crop on its own.
request Copy 
{
"image_url": "<object_url>",
"layout_config": {
"side_by_side": { "focus_y": 25, "split_size": "35%", "approved": true },
"top_bottom": { "focus_y": 25, "approved": true },
"round_overlay": {
"horizontal": { "zoom": 1.2, "focus_y": 20 },
"vertical": { "zoom": 1.2, "focus_y": 20 },
"approved": true
}
},
"avatar_position": "right-bottom"
} 

200 response Copy 
{
"success": true,
"previews": [
{
"layout": "side_by_side",
"orientation": "horizontal",
"frame_preview_url": "https://…png", // presenter in the video frame
"preview_url": "https://…png", // presenter crop alone
"position": "right-bottom",
"presenter_fits": true,
"split_size": "35%",
"crop": { "x": 0.05, "y": 0.0, "width": 0.9, "height": 1.0 }
}
// … top_bottom, round_overlay ×2, fullscreen ×2
],
"available_layouts": ["side_by_side", "top_bottom", "round_overlay"],
"unavailable_layouts": ["fullscreen"],
"side_by_side_safe_split_sizes": ["25%", "30%", "35%"]
} 

Approve a layout ( approved: true ) only when presenter_fits is true for every orientation it renders in. If a face is cut off, lower the Vertical position ( focus_y ) to move the crop up, or reduce zoom . Both image URLs are valid for 1 hour. Previews are limited to 20 per minute per account.

3 Create the avatar
POST {BASE_URL} /api/v2/avatars 
Send the same layout_config you previewed.
request Copy 
{
"name": "Priya",
"mode": "direct",
"source_image_url": "<object_url>",
"consent_confirmed": true,
"layout_config": { … }
} 

201 response Copy 
{
"success": true,
"avatar": {
"id": "38521eff-b743-4a34-bc39-589283f8a3e5",
"name": "Priya",
"mode": "direct",
"status": "ready",
"preview_url": "https://…png",
"layout_config": { … },
"approved_layouts": ["side_by_side", "top_bottom", "round_overlay"],
"available_layouts": ["side_by_side", "top_bottom", "round_overlay"],
"layout_compatibility": { … }
}
} 

Field Required Description 
name Yes Display name. 
source_image_url Yes The object_url from step 1. 
consent_confirmed Yes Image use confirmation. Must be true: "I confirm that I own this image or have permission to use and animate this person's photo." 
mode No Presenter style. direct = Natural avatar (default): uses your original portrait and approved framing, ready immediately, no creation credit. Returns 201 with status: "ready" . polished_3d = Polished avatar : an AI-styled portrait that keeps your recognizable appearance, 1 credit after successful creation. Returns 202 with status: "processing" . 
layout_config No Framing and approval per layout. Omitted layouts use defaults and stay unapproved. 
instructions No Polished avatar only: styling directions, such as "navy blazer, soft studio light". 
generation_orientation No Polished avatar formats: both (default, recommended), horizontal (16:9 videos), or vertical (9:16 videos). 
normalized_image_url No Your own 720×1280 crop. If omitted, Golpo center-crops the portrait. 

4 Wait for Polished avatars
GET {BASE_URL} /api/v2/avatars/{avatar_id} 
Natural avatars are Ready immediately. For a Polished avatar, poll every 15–30 seconds until status is ready or failed ; it usually takes a few minutes. A Failed avatar can be retried with POST /avatars/ {avatar_id} /retry .
status Playground label Meaning 
processing Processing The Polished avatar is being created. 
pending_approval Finalizing Created and waiting to be finished. Call POST /avatars/ {avatar_id} /approve . 
ready Ready Ready for AI Presenter videos. 
failed Failed Avatar creation failed; retry it or delete it. 

Layout & Framing
How the presenter is placed in the video, and how to frame the crop for each layout. Names match the playground's AI Presenter panel.

Side by side
side_by_side 
Landscape 16:9. Presenter left or right of content; Presenter size sets its width.

Top and bottom
top_bottom 
Portrait 9:16. Presenter above or below content. Videos request it as side_by_side; vertical videos render it as Top and bottom.

Round overlay
round_overlay 
Circular corner overlay, in the corner set by avatar_position. Content stays full frame.

Full screen
fullscreen 
Presenter fills the complete frame. Auto can switch to it for some scenes.

layout_config fields
Layout Fields Used for 
side_by_side zoom, focus_x, focus_y, split_size, approved Side by side, Landscape 16:9 
top_bottom zoom, focus_x, focus_y, approved Top and bottom, Portrait 9:16 
round_overlay horizontal {…} , vertical {…} , approved Round overlay, both formats, cropped separately 
fullscreen horizontal {…} , vertical {…} , approved Full screen, both formats, cropped separately 

Field Playground control Values 
zoom Zoom (Wider / Closer) 1.0 (no zoom) to 2.0. 
focus_x Horizontal position (Left / Right) 0 to 100, where 50 is centered. 
focus_y Vertical position (Up / Down) 0 to 100, where 50 is centered. Lower values move the crop toward the top of the photo. 
split_size Presenter size 25%, 30%, 35%, 40%, or 50%. Prefer a value from side_by_side_safe_split_sizes . 
approved Approve this layout true saves your crop and makes the layout available for Auto or manual selection. Golpo may also enable an unapproved layout when its default crop fits safely. 

NOTE: Framing is saved with the avatar and locked once it is Ready. To change it, create a new avatar. PUT /avatars/ {avatar_id} /layout-config only works while a Polished avatar is still Processing; on a Ready avatar it returns 409. 

Reading the result
Field Meaning 
approved_layouts Layouts you approved in layout_config. 
available_layouts Layouts this avatar can actually render. Pass one of these as avatar_layout, or use auto. 
layout_compatibility Details per layout: safe split sizes, and the reason a layout is unavailable (for example face_cropped). 

Generate Presenter Videos
Add the AI Presenter fields to a normal POST /api/v2/videos/generate request.

Parameter Type Default Description 
avatar_id string null A Golpo avatar id, or the id of one of your Ready custom avatars. 
avatar_layout enum auto Layout. auto = Auto (uses approved layouts automatically), side_by_side = Side by side in horizontal videos and Top and bottom in vertical videos, round_overlay = Round overlay, fullscreen = Full screen. 
avatar_position enum right-bottom Placement: left-top , right-top , left-bottom , or right-bottom . Round overlay uses it as the corner. Side by side uses the side (Presenter left / Presenter right); Top and bottom uses top or bottom (Presenter top / Presenter bottom). 
avatar_split_size enum saved, else 30% Presenter size: 25%, 30%, 35%, 40%, or 50% of the width (Side by side) or height (Top and bottom). Not valid with round_overlay. 
avatar_framing object null The orientation_framing from video preflight, to accept a best-effort crop. 
custom_videos_avatar_modes object null Avatar during this clip, per inserted video, keyed by its 1-based position in custom_videos : off = Hide avatar (video uses the full frame), round_overlay = Show avatar (round corner overlay). 

Rules
Every other avatar_* field requires avatar_id .
avatar_id takes the presenter slot, so it can't be combined with own_narration_video_layout or own_narration_video_mode: true .
own_narration_source still works: the avatar lip-syncs your recorded audio, and billing follows the narration length (up to 15 minutes).
Avatar fields are rejected with enable_podcast_engine: true .
A layout the avatar can't render returns 422 with code avatar_layout_unavailable . Pick from available_layouts , or use auto .
Credits are checked before the job starts. Without enough credits you get 402 and no job is created.

Track Progress
Avatar videos use the usual job status endpoint, with an extra avatar object.

GET {BASE_URL} /api/v2/videos/status/{job_id} 
while rendering Copy 
{
"job_id": "9dd38c69-…",
"status": "processing",
"video_url": null,
"avatar": { "layout": "side_by_side", "stage": "queued" }
} 

when done Copy 
{
"job_id": "9dd38c69-…",
"status": "completed",
"video_url": "https://…/avatar-composed/….mp4",
"avatar": { "layout": "side_by_side", "stage": "composed" }
} 

avatar.stage Meaning 
null The base video is still being generated; the presenter hasn't started. 
queued The presenter render is queued. 
running The presenter is being rendered and lip-synced. 
waiting_for_shared_avatar Another video is rendering the same presenter; this job reuses it. 
succeeded The presenter is rendered and the final video is being composed. 
composed Done. status is completed and video_url is the final video. 
failed The avatar step failed. status is failed and error explains why. 

video_url stays null until status is completed , so you never receive a video without the presenter. Avatar videos take longer than standard videos; poll every 15–30 seconds. 
Full Example
Upload a portrait, preview its layouts, create the avatar, and generate a video.

JavaScript Python cURL 
avatar-video.js Copy 
import fetch, { FormData, fileFromSync } from "node-fetch";

const API_KEY = "api-key";
const BASE_URL = "{BASE_URL}";
const headers = { "x-api-key": API_KEY };
const json = { ...headers, "Content-Type": "application/json" };

// 1. Upload a portrait (PNG, JPEG, or WebP, up to 10 MB)
const form = new FormData();
form.set("image", fileFromSync("./portrait.png", "image/png"));
form.set("kind", "source");
const { upload } = await (await fetch(`${BASE_URL}/api/v2/avatars/upload`, {
method: "POST", headers, body: form,
})).json();

// 2. Preview every layout before creating the avatar (free)
const layout_config = {
side_by_side: { focus_y: 40, split_size: "35%", approved: true },
top_bottom: { focus_y: 40, approved: true },
round_overlay: { horizontal: { zoom: 1.3 }, vertical: { zoom: 1.3 }, approved: true },
};
const preview = await (await fetch(`${BASE_URL}/api/v2/avatars/layout-preview`, {
method: "POST", headers: json,
body: JSON.stringify({ image_url: upload.object_url, layout_config }),
})).json();
preview.previews.forEach((p) =>
console.log(p.layout, p.orientation, p.presenter_fits, p.preview_url));

// 3. Create the avatar with the same layout_config
const { avatar } = await (await fetch(`${BASE_URL}/api/v2/avatars`, {
method: "POST", headers: json,
body: JSON.stringify({
name: "Priya",
mode: "direct", // Natural avatar; "polished_3d" = Polished avatar
source_image_url: upload.object_url,
consent_confirmed: true,
layout_config,
}),
})).json();
console.log(avatar.id, avatar.available_layouts);

// 4. Generate a video with the avatar
const job = await (await fetch(`${BASE_URL}/api/v2/videos/generate`, {
method: "POST", headers: json,
body: JSON.stringify({
prompt: "Why the sky is blue",
timing: "1",
avatar_id: avatar.id, // or a Golpo avatar id such as "stock-maya-v1"
avatar_layout: "side_by_side", // side_by_side | round_overlay | fullscreen | auto
}),
})).json();
console.log(job.job_id); 
Poll GET /api/v2/videos/status/{job_id}. While the presenter renders, status is "processing" and avatar.stage reports progress.

Errors
Errors return the standard error body with a detail field.

Status When 
402 Not enough credits at the avatar rate 
403 Called with a portal session token instead of an API key 
404 Avatar or Golpo avatar id not found, or owned by another account 
409 Custom avatar not Ready, or framing changed after the avatar is Ready 
422 Image use not confirmed (consent_confirmed not true), invalid layout_config, rejected image, avatar_layout_unavailable, or avatar_id combined with own-narration layout fields 
429 More than 20 layout previews in a minute 
503 Person detection or the avatar service is temporarily unavailable; retry 

Upload File
Use /api/v2/videos/upload-file to get a hosted URL before calling /generate.

NOTE: File size must be less than 10 MB . Larger files are rejected with HTTP 413. The upload endpoint is gated to Business Plus plans. 

NOTE: Document URLs are single-use. When you pass a document URL (PDF, DOCX, TXT, etc.) from /upload-file into reference_source , the file is permanently deleted from storage after its text is extracted during generation. The same URL cannot be reused for another video or podcast — you must upload the document again via /upload-file to get a fresh URL for each new generation. 

Content-Type: multipart/form-data 
Field Type Required Description 
file File Yes Single file to upload (file metadata is used to generate a presigned URL). 

Documents
PDF · DOC · DOCX · TXT · MD · CSV · XLSX · XLS · PPT · PPTX

Audio
MP3 · WAV · M4A · OGG · FLAC

Video
MP4 · MOV · M4V · AVI · MKV · WEBM

Images
JPG · JPEG · PNG · GIF · WEBP

upload-file.js Copy 
const API_KEY = "api-key";
const BASE_URL = "{BASE_URL}";

// Step 1: Get presigned URL
async function uploadFile(file) {
const formData = new FormData();
formData.append('file', file);

const response = await fetch(`${BASE_URL}/api/v2/videos/upload-file`, {
method: 'POST',
headers: { 'x-api-key': API_KEY },
body: formData
});

const { upload_url, file_url, content_type } = await response.json();

// Step 2: Upload bytes to the presigned URL
await fetch(upload_url, {
method: 'PUT',
headers: { 'Content-Type': content_type },
body: file
});

// Step 3: Return file_url for use in /generate
return file_url;
}

// Usage
const fileInput = document.querySelector('#file-input');
const fileUrl = await uploadFile(fileInput.files[0]);
console.log('File uploaded, URL:', fileUrl);
// Use fileUrl in your /generate request (reference_source, custom_logo, etc.)

const API_KEY = "api-key";
const BASE_URL = "{BASE_URL}";

// Step 1: Helper to upload a file via /upload-file
async function uploadFile(file) {
const formData = new FormData();
formData.append('file', file);

const presign = await fetch(`${BASE_URL}/api/v2/videos/upload-file`, {
method: 'POST',
headers: { 'x-api-key': API_KEY },
body: formData
});
const { upload_url, file_url, content_type } = await presign.json();

await fetch(upload_url, {
method: 'PUT',
headers: { 'Content-Type': content_type },
body: file
});

return file_url;
}

// Step 2: Upload all reference docs and collect URLs
const fileInput = document.querySelector('#uploads');
const referenceUrls = await Promise.all(
Array.from(fileInput.files).map((f) => uploadFile(f))
);

// Step 3: Generate the video with the uploaded references
const generatePayload = {
prompt: 'Summarize this slide deck for executives',
reference_source: referenceUrls,
narration_voice: 'female-1',
narration_language: 'spanish'
};

const response = await fetch(`${BASE_URL}/api/v2/videos/generate`, {
method: 'POST',

Custom Style (Canvas + Sketch)
Render a video in a look derived from your own reference. Save the style once via POST /api/v2/custom-styles , then pass its id as custom_style — the same saved style works with both engines.

Step 1 — save the style (once): POST /api/v2/custom-styles with style_name + source (image URL, video URL, or text). See Custom Style Endpoints . Step 2 — generate : pick the engine and pass the returned id in custom_style . Requires the Business plan or above. 

Golpo Canvas golpo_canvas 
Full-colour composed scenes that closely follow the reference’s palette, texture and composition. custom_style replaces canvas_style_variant . pen_animation_style and visual_animation_style can still be combined with it.

Golpo Sketch golpo_sketch 
Progressive line-drawing reveal using the reference’s derived palette and texture — the “sketch” character stays dominant. custom_style replaces sketch_style_variant .

Custom Style Workflow
POST /custom-styles → POST /videos/generate 
Full step-by-step pattern: create a custom style from an image URL (1a), a text description (1b), and a video URL (1c), then pass the returned id as custom_style on /generate. All three work with either engine.
JavaScript Python .NET Java curl 
custom-style-workflow.js Copy 
import fetch from "node-fetch";

const API_KEY = "api-key"; // Replace with your Golpo API key
const BASE_URL = "{BASE_URL}"; // You will receive this when creating an API key
const headers = { "Content-Type": "application/json", "x-api-key": API_KEY };

// ── Step 1a: create a custom style from an IMAGE URL ─────────────────────────
// Tip: host your own image with POST /api/v2/videos/upload-file and use file_url.
const imageStyleRes = await fetch(`${BASE_URL}/api/v2/custom-styles`, {
method: "POST",
headers,
body: JSON.stringify({
style_name: "Brand moodboard",
source: "https://cdn.example.com/brand-moodboard.png",
kind: "image"
})
});
const imageStyleId = (await imageStyleRes.json()).style.id;
console.log("Image style id:", imageStyleId);

// ── Step 1b: create a custom style from a TEXT description ───────────────────
const textStyleRes = await fetch(`${BASE_URL}/api/v2/custom-styles`, {
method: "POST",
headers,
body: JSON.stringify({
style_name: "Flat vector",
source: "Flat vector illustration, navy and coral palette, thick rounded outlines, generous whitespace",
kind: "text"
})
});
const textStyleId = (await textStyleRes.json()).style.id;
console.log("Text style id:", textStyleId);

// ── Step 1c: create a custom style from a VIDEO URL ──────────────────────────
// Frames are sampled from the clip and analyzed for the still art style.
const videoStyleRes = await fetch(`${BASE_URL}/api/v2/custom-styles`, {
method: "POST",
headers,
body: JSON.stringify({
style_name: "Brand reel",
source: "https://cdn.example.com/brand-reel.mp4",
kind: "video"
})
});
const videoStyleId = (await videoStyleRes.json()).style.id;
console.log("Video style id:", videoStyleId);

// ── Step 2: generate a video with one of the saved styles ────────────────────
const generateRes = await fetch(`${BASE_URL}/api/v2/videos/generate`, {
method: "POST",
headers,
body: JSON.stringify({
prompt: "How photosynthesis works",
golpo_video_engine: "golpo_canvas", // or "golpo_sketch" — same style id works
custom_style: imageStyleId, // or textStyleId / videoStyleId
timing: "1"
})
});
const job = await generateRes.json();
console.log("Job ID:", job.job_id);

// ── Step 3: poll for completion ──────────────────────────────────────────────
// GET ${BASE_URL}/api/v2/videos/status/${job.job_id} (see Job Status) 
Run with: node --env-file=.env custom-style-workflow.js

Editing workflow
frame-versions edit-frames edits/{id}/status combine-frames final video 
set-frame-version is optional — use it to revert a frame to an earlier take from its version history. Both edit-frames and combine-frames are async; poll their job IDs at the shared edits/{edit_job_id}/status endpoint.

1 List Frame Versions

GET /api/v2/videos/{video_id}/frame-versions 
Return the per-frame animation history for a sketch video — the currently active MP4 for each frame plus every previous version. Use this to discover frame indices before editing or to find a URL to revert to. Requires x-api-key.

JavaScript Python curl 
frame-versions.js Copy 
import fetch from "node-fetch";

const BASE_URL = "{BASE_URL}"; // You will receive this when creating an API key
const VIDEO_ID = "video_id"; // a completed Golpo Sketch video

const response = await fetch(
`${BASE_URL}/api/v2/videos/${VIDEO_ID}/frame-versions`,
{ headers: { "x-api-key": "api-key" } }
);

const data = await response.json();
// {
// video_id: "...",
// frame_animations: { "0": "https://...0.mp4?v=...", "1": "..." }, // active per frame
// frame_animation_versions: { "0": [{ url, ts, note }, ...] } // full history per frame
// }
console.log(data.frame_animations); 
Run with: node --env-file=.env frame-versions.js

2 Edit Frames

POST /api/v2/videos/{video_id}/edit-frames 
Re-render one or more frames from natural-language instructions. frame_ids and edit_prompts must be the same length (one prompt per frame). Each frame returns its own pollable edit_job_id. Requires x-api-key.

JavaScript Python curl 
edit-frames.js Copy 
import fetch from "node-fetch";

const BASE_URL = "{BASE_URL}";
const VIDEO_ID = "video_id";

// frame_ids[i] is edited using edit_prompts[i] — the two arrays must match in length.
// reference_images is optional style guidance (https/s3 URLs).
const payload = {
frame_ids: ["0", "2"],
edit_prompts: [
"Make the title text blue and bolder",
"Add an arrow pointing to the diagram"
],
reference_images: ["https://example.com/style.png"] // optional
};

const response = await fetch(
`${BASE_URL}/api/v2/videos/${VIDEO_ID}/edit-frames`,
{
method: "POST",
headers: { "Content-Type": "application/json", "x-api-key": "api-key" },
body: JSON.stringify(payload)
}
);

const data = await response.json();
// {
// video_id: "...", status: "processing", message: "Started 2 frame edit job(s)",
// edit_jobs: [{ frame_id: "0", edit_job_id: "..." }, { frame_id: "2", edit_job_id: "..." }]
// }
// Poll each edit_job_id at GET /api/v2/videos/edits/{edit_job_id}/status.
console.log(data.edit_jobs); 
Run with: node --env-file=.env edit-frames.js

3 Edit Job Status

GET /api/v2/videos/edits/{edit_job_id}/status 
Poll the status of a frame edit or combine job. This endpoint supports both /edit-frames and /combine-frames jobs. Returns 'processing', a 'completed' result with the MP4 url, or 'failed' with an error message. Requires x-api-key.

JavaScript Python curl 
edit-status.js Copy 
import fetch from "node-fetch";

const BASE_URL = "{BASE_URL}";
const EDIT_JOB_ID = "edit_job_id"; // from /edit-frames or /combine-frames

const response = await fetch(
`${BASE_URL}/api/v2/videos/edits/${EDIT_JOB_ID}/status`,
{ headers: { "x-api-key": "api-key" } }
);

const data = await response.json();
// { status: "processing" } -> still rendering
// { status: "completed", url: "https://...mp4" } -> edited frame / combined video
// { status: "failed", error: "..." }
console.log(data.status, data.url ?? ""); 
Run with: node --env-file=.env edit-status.js

4 Combine Frames

POST /api/v2/videos/{video_id}/combine-frames 
Concatenate per-frame MP4s into a fresh final video, muxing audio from the original render. You must pass exactly one URL per frame, in order (a count mismatch returns 422). Mix edited URLs (from /edit-frames) with the unchanged frame_animations URLs (from /frame-versions). Returns a combine_job_id to poll via the status endpoint. Requires x-api-key.

JavaScript Python curl 
combine-frames.js Copy 
import fetch from "node-fetch";

const BASE_URL = "{BASE_URL}";
const VIDEO_ID = "video_id";

// One MP4 per frame, in order: edited URLs for frames you changed, and the
// existing frame_animations URLs (from /frame-versions) for the rest.
const payload = {
frame_animation_urls: [
"https://.../frame-0-edited.mp4",
"https://.../frame-1.mp4",
"https://.../frame-2-edited.mp4"
]
};

const response = await fetch(
`${BASE_URL}/api/v2/videos/${VIDEO_ID}/combine-frames`,
{
method: "POST",
headers: { "Content-Type": "application/json", "x-api-key": "api-key" },
body: JSON.stringify(payload)
}
);

const data = await response.json();
// { combine_job_id: "...", video_id: "...", status: "processing" }
// Poll GET /api/v2/videos/edits/{combine_job_id}/status for the final video URL.
console.log(data.combine_job_id); 
Run with: node --env-file=.env combine-frames.js

5 Set Frame Version

POST /api/v2/videos/{video_id}/set-frame-version 
Make a specific animation version the active one for a frame — e.g. revert to an earlier take. The frame_animation_url should come from frame_animation_versions[frame_id] returned by /frame-versions. The response returns the activated URL. Requires x-api-key.

JavaScript Python curl 
set-frame-version.js Copy 
import fetch from "node-fetch";

const BASE_URL = "{BASE_URL}";
const VIDEO_ID = "video_id";

// v2 names this field "frame_animation_url" (v1 calls it "url"). It should be one
// of the versions listed in frame_animation_versions[frame_id] from /frame-versions.
const payload = {
frame_id: "0",
frame_animation_url: "https://.../frame-0-v2.mp4"
};

const response = await fetch(
`${BASE_URL}/api/v2/videos/${VIDEO_ID}/set-frame-version`,
{
method: "POST",
headers: { "Content-Type": "application/json", "x-api-key": "api-key" },
body: JSON.stringify(payload)
}
);

const data = await response.json();
// { video_id: "...", frame_id: "0", frame_animation_url: "https://.../frame-0-v2.mp4?v=..." }
console.log(data.frame_animation_url); 
Run with: node --env-file=.env set-frame-version.js

Frame Transition
frame_transition controls how a finished frame moves into the next one. It works with both Golpo Canvas and Golpo Sketch . Without it, every frame change is a hard cut.

Value Description 
"none" Hard cut, no animation (Default). 
"left" The next frame slides in from the right, pushing the current frame out to the left. 
"right" The next frame slides in from the left, pushing the current frame out to the right. 
"up" The next frame slides in from the bottom, pushing the current frame out the top. 
"down" The next frame slides in from the top, pushing the current frame out the bottom. 
"zoom_in" The current frame zooms in while the next frame grows into place and blends in. 
"zoom_out" The current frame zooms out and fades away, revealing the next frame. 

frame_transition is an array of strings . Send one value for the same effect on every frame change, or several values to have Golpo pick one of them at random for every frame change . For example, ["left", "zoom_in"] mixes slides to the left with zoom-ins.
The transition plays between two frames, so the last frame and the frames next to a clip you inserted with custom_videos always use a hard cut. 
Hand animation
Set transition_hand_animation to true to have an animated hand push each slide to the next frame. It defaults to false and accepts only true or false . It needs at least one slide effect ( left , right , up , down ) in frame_transition and cannot be combined with zoom_in or zoom_out .
NOTE: Frame transitions are only available with scene_pacing: "normal" (the default). Sending any value other than ["none"] — or transition_hand_animation: true — together with scene_pacing: "fast" is rejected with 422. 
Ready-to-send payloads are in the Frame Transition example .

Inserting Images in Script
How to place paired [START][IMAGE N] and [END][IMAGE N] markers inside custom_script so your uploaded custom_images land at the right moment in the narration.

When you supply your own script via custom_script and also upload custom_images , wrap a sentence in paired markers to control where each image appears. [IMAGE 1] refers to the first image in custom_images , [IMAGE 2] to the second, and so on (marker numbers start at 1, not 0). The image displays for the duration of the spoken text between [START][IMAGE N] and [END][IMAGE N] .
Follow these rules to make sure your image inserts are never silently skipped:
Use 1 for your first uploaded image, 2 for the second, and so on. [IMAGE 1] → first item in custom_images . If you write [IMAGE 3] but only uploaded 2 images, that image won’t appear.
Every [START][IMAGE N] needs a matching [END][IMAGE N] with the same number. Missing or mismatched closing tags drop the marker.
Put whitespace around marker tags when they sit next to sentence punctuation. Always leave a space (or newline) between the preceding sentence's period and [START] , and between [END][IMAGE N] and the next sentence. Write story. [START][IMAGE 2] and [END][IMAGE 1] Next sentence. — never story.[START][IMAGE 2] or [END][IMAGE 1]Next sentence. . Without these spaces the sentence splitter cannot find a clean break and the marker is dropped.
Wrap a complete, simple sentence of 8–15 plain words between the markers. Shorter than 5 words is fragile; longer than 20 holds the image on-screen too long.
Avoid colons ( : ), em-dashes ( — ), semicolons ( ; ), and parentheses inside the marker span. 
Keep commas inside the marker to at most one or two. Stacked lists like "not X, not Y, not Z" confuse the matcher.
NOTE: Image markers that violate any of these rules are silently dropped — no error, no warning. The frame at that position falls back to an AI-generated visual and your uploaded image never appears. 
Example 1 — Good shape (use as a template): 
image-markers-good-shape.json Copy 
{
"custom_script": "Travel changes how we see the world. [START][IMAGE 1] This is a quiet beach at sunset with golden waves rolling onto soft sand. [END][IMAGE 1] Coastal trips help us slow down and breathe deeply for a few days. [START][IMAGE 2] This is a mountain village tucked between tall green peaks and clouds. [END][IMAGE 2] Highland trips reward you with cool air and stunning scenic views.",
"custom_images": [
"https://example.com/beach.png",
"https://example.com/mountain.png"
],
"custom_images_description": [
"A quiet beach at sunset",
"A mountain village among green peaks"
]
} 

Each wrapped sentence is ~10–12 plain words, contains no colons or em-dashes, has a single space after each preceding period, and the marker numbers (1, 2) match the 2-item custom_images array.
You can also use other image control parameters alongside the markers: keep_original_images (boolean array — skip AI processing and place the image untouched) and disable_image_animation (boolean array — render as a static frame instead of an animated drawing).
Example 2 — Common mistakes and their fixes: 
image-markers-missing-space.json Copy 
// ❌ Mistake A: no space BEFORE [START] — IMAGE 2 won't appear
{
"custom_script": "...each region tells a unique story.[START][IMAGE 2] Rajasthan glows proudly with royal forts and deserts[END][IMAGE 2]."
}

// ✅ Fix A: add a single space between "story." and "[START][IMAGE 2]"
{
"custom_script": "...each region tells a unique story. [START][IMAGE 2] Rajasthan glows proudly with royal forts and deserts[END][IMAGE 2]."
}

// ❌ Mistake B: no space AFTER [END] — IMAGE 1 won't appear
{
"custom_script": "[START][IMAGE 1] A coastal town glows at sunset by the harbor. [END][IMAGE 1]The next morning brings calm waters and a quiet beach."
}

// ✅ Fix B: add a single space between "[END][IMAGE 1]" and "The"
{
"custom_script": "[START][IMAGE 1] A coastal town glows at sunset by the harbor. [END][IMAGE 1] The next morning brings calm waters and a quiet beach."
} 

Inserting Videos in Script
How to place paired [START][VIDEO N]...[END][VIDEO N] markers inside custom_script so your uploaded custom_videos play for the right span of narration.

When you supply your own script via custom_script and also upload custom_videos , wrap the narration that should play over video N with a paired [START][VIDEO N] ... [END][VIDEO N] block — the same shape used for image markers. [VIDEO 1] refers to the first video in custom_videos , [VIDEO 2] to the second, and so on (marker numbers start at 1, not 0). The narration text between the [START] and [END] markers determines the on-screen duration of the user video — the engine cuts to your clip at the START marker and returns to AI-generated visuals at the END marker.
Follow these rules to make sure your video inserts are never silently skipped:
Use 1 for your first uploaded video, 2 for the second, and so on. [VIDEO 1] → first item in custom_videos . If you write [VIDEO 3] but only uploaded 2 videos, that video won’t appear.
Every video needs a matching [START] and [END] pair. Use the shape [START][VIDEO N] ... narration ... [END][VIDEO N] . Writing a bare [VIDEO N] without the wrappers causes the engine to start the video but never stop it — it will keep playing over all subsequent narration and block any later [VIDEO N] blocks from rendering.
Spelling and casing must be exact. Use uppercase VIDEO with a single space before the number — typos like [VEIDO 1] or [VDIEO 1] are silently dropped.
Always put whitespace around each marker. Write Welcome. [START][VIDEO 1] Here is the footage. [END][VIDEO 1] Up next. — never glue markers to surrounding words.
Place markers at sentence boundaries, not mid-sentence. Put [START][VIDEO N] right before the first word of the sentence the video should cover, and [END][VIDEO N] right after the closing punctuation of the last sentence in that block.
Match the narration length to the user video’s original duration. The engine treats the uploaded clip’s natural length as authoritative — [END][VIDEO N] does not force a hard cut. If the clip is longer than the narration wrapped inside the block, the video keeps playing past [END] and the next narration line is delayed until the clip finishes, producing a visible silent gap. Either pre-trim the clip before uploading, or expand the narration inside the block to cover the clip’s full runtime.
Each [VIDEO N] appears exactly once. One [START] and one [END] per video — do not reuse the same N later in the script.
Do not nest video blocks. [START][VIDEO 1] ... [START][VIDEO 2] ... [END][VIDEO 1] [END][VIDEO 2] is invalid; each block must fully close before the next one opens.
NOTE: Video markers that violate any of these rules are silently dropped — no error, no warning. The position falls back to the engine's normal narration without your uploaded video. 
NOTE: Heads up — clip duration vs. narration duration. The user video plays for its full uploaded length regardless of how much narration you wrap between [START][VIDEO N] and [END][VIDEO N] . If the clip is longer than the wrapped narration, the video keeps playing past [END] silently, and the next narration line is held back until the clip ends. To avoid this silent gap, either trim the clip to roughly the spoken duration of the wrapped sentences before uploading, or write enough narration inside the block to cover the clip’s full runtime. 
Example — Good shape (use as a template): 
video-markers-good-shape.json Copy 
{
"custom_script": "Welcome to today's nature tour. [START][VIDEO 1] Here is a stunning view of the mountain ridge captured from the air. [END][VIDEO 1] Now let us head down to the coast. [START][VIDEO 2] These calming waves close out our journey. [END][VIDEO 2] Thanks for watching.",
"custom_videos": [
"https://example.com/mountain-clip.mp4",
"https://example.com/coastal-clip.mp4"
],
"custom_videos_description": [
"Aerial view of a mountain ridge",
"Coastal waves rolling onto a beach"
]
} 

Each [VIDEO N] appears twice — once with [START] at the beginning of its sentence and once with [END] at the end. Video 1 plays only over “Here is a stunning view… from the air.” , then the engine returns to AI-generated visuals for “Now let us head down to the coast.” , then video 2 plays only over “These calming waves close out our journey.” Marker numbers (1, 2) match the 2-item custom_videos array. To control whether the video plays with its original audio or AI narration, see use_ai_audio_at .

Code Meaning Recovery

Error Response Format
All 4xx and 5xx responses return a JSON body with a detail field.

String detail 
Most errors return detail as a single human-readable string describing what went wrong. Surface it directly in your UI or logs.
error-response-string.json Copy 
{
"detail": "'canvas_style_variant' is required when using 'golpo_canvas' engine."
} 

Array detail 
When the request body fails validation, detail is an array of error objects — one per failing field. Each object includes the failing field path ( loc ) and a human-readable message ( msg ).
error-response-array.json Copy 
{
"detail": [
{
"type": "value_error",
"loc": ["body"],
"msg": "Value error, 'custom_videos_description' is required when 'custom_videos' is provided. Provide one description per video (2 expected)."
}
]
}
